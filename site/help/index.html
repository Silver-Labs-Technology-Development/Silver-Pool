COMMON PROBLEMS

Symptoms and what they mean

These are actual rejection reasons and API states produced by this pool, not generic suggestions.

No Stratum endpoint is shown

The operator has not set BTCS_PUBLIC_STRATUM_HOST. The pool may be listening locally, but it is not advertising an address that miners can reach. Do not connect to 127.0.0.1 from another machine, and do not use a hostname from an old example.

Return to the connection guide

Connection refused or timed out

Check the exact host and port, TCP firewall rules and whether the pool is listening. A DNS name resolving on the web server does not prove that the Stratum port is reachable. Test with nc -vz HOST PORT or telnet HOST PORT.

Authorization failed

The username must match ACCOUNT.WORKER using letters, digits, ., _, :, @, + or -, with a maximum of 160 characters. If the operator configured a pool password, the password must match exactly. A blank username is rejected.

Repeated “low-difficulty”

The submitted hash did not meet the share target for your session. This is not a block rejection. Confirm the miner is using SHA256d and received mining.set_difficulty; if you requested mining.suggest_difficulty, the pool applies that difficulty to your session.

Repeated “stale-job”

The job was built for a previous block tip. After a new block arrives, finish the current job promptly; submissions referencing the old previous block hash are recorded as stale and are not counted as valid work.

“duplicate-share”

The same miner, job, extranonce2, ntime and nonce were already submitted. The database rejects the duplicate so it cannot be counted twice. Reconfigure the miner or use a fresh job; do not simply resubmit.

“invalid-extranonce2” or “invalid-hex”

The submission did not match the extranonce2 size advertised during subscribe, or a field was not valid hexadecimal. Use the exact extranonce2 size from mining.subscribe and 8-character ntime/nonce fields.

Pool status says “not ready”

Read Service Status. Readiness requires a healthy database, a connected and synced BTCS node, a listening Stratum server and a fresh getblocktemplate job. Mining values are not inferred while a component is unavailable.

Miner is not found

Public miner pages only contain accounts that have authorized at least once and remain in the persistent database. Check the account spelling; worker suffixes are not separate miner accounts. A miner with no accepted shares still appears after authorization.

Balances are displayed but cannot be withdrawn

Payouts are disabled in this release. The pool records share weights, block rewards, fees and maturity state, but it does not sign or broadcast miner payments. Do not send a private key, seed phrase or exchange password; none is required.

API returns an error envelope

Errors have "ok": false and an error.code such as not_ready, invalid_username, rate_limited or miner_not_found. Use the API documentation and the returned HTTP status; do not parse an error as a successful empty result.

Website is up but data is offline

The static site can load while the API or node is down. In that case the pages show an offline or error state and clear the live figure rather than presenting a stale or invented number.

What to send an operator

If the checks above do not explain the problem, include:

  • The miner software and version.
  • The exact rejection message from the miner log.
  • The pool endpoint host and port, but never a password or private key.
  • The time the problem occurred and your timezone.
  • Whether Status reported ready at that time.

What the pool will never ask for

Silver Pool does not need a wallet private key, seed phrase, exchange login or signing credential to accept shares. The Stratum username is a public accounting label. Treat any request for those secrets as fraudulent.
