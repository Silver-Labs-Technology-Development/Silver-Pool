HOW IT WORKS

What happens after you connect

  1. Subscribe and authorize. The pool returns a session-specific extranonce1 and accepts your ACCOUNT.WORKER identity.
  2. Receive a job. Every job is built from a real getblocktemplate response from BTCS Core, including merkle branches and the current network target.
  3. Submit shares. Each share is checked against the session difficulty. Duplicate, stale, malformed and low-difficulty submissions are rejected with a reason.
  4. Block candidates. If a share also meets the network target, the assembled block is submitted with submitblock. Only node-accepted blocks are recorded as blocks.

Never send private keys. Silver Pool never needs a wallet private key, seed phrase or exchange password. The Stratum username is an accounting label, not a signing credential.
